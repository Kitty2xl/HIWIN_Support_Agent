## 1. 系統是什麼

一套 HIWIN 產品的**問答服務**。使用者把問題送到後端的 `POST /chat`，後端在本地的
PostgreSQL（pgvector）知識庫中檢索型錄內容，交給本地的 llama.cpp 模型作答，回傳含
頁碼引用與圖示的 Markdown 答覆。

系統由三個部分組成，都在同一台機器上：

```
PDF 型錄 ─▶ 管線 pipeline/（把 PDF 轉成可檢索的資料）─▶ PostgreSQL 資料庫 hiwin_rag_db
                                                              │
使用者 ─▶ POST /chat ─▶ 後端（埠 8079）◀──────── llama.cpp 路由（埠 11400，四個模型常駐）
```

| 部分 | 功用 | 何時需要它 |
|---|---|---|
| **llama.cpp 路由**（`llama-server`） | 載入 AI 模型（對話、向量化、重排序、輔助） | 只要要回答問題或跑管線，就要開著 |
| **後端**（`main.py`，uvicorn） | 提供 `/chat` API 與展示頁 | 要回答問題時 |
| **PostgreSQL** | 存放型錄內容與對話記錄 | 永遠要開著（Windows 服務，開機自動啟動） |
| **管線**（`pipeline/`） | 把新的 PDF 匯入資料庫 | 只在新增／更新型錄時 |

**三個設定檔必須一致**，這是最常見的問題來源：

| 檔案 | 管什麼 |
|---|---|
| `config.ini` | 路由要載入哪些模型檔（GGUF 的絕對路徑）、每個模型的參數 |
| `.env` | 後端：連哪個資料庫、向路由要哪些模型名稱、圖片資料夾 |
| `pipeline/settings.json` | 管線：資料根目錄、圖片資料夾、資料庫、各步驟用的模型名稱 |

不用背；`python doctor.py --all` 會逐項檢查並告訴你哪裡不一致、怎麼修。

## 4. 安裝

### 4.1 取得程式

```bash
git clone https://github.com/Kitty2xl/HIWIN_Support_Agent
cd HIWIN_Support_Agent
```

（若沒有網路，直接複製整個資料夾也可以；`.gitattributes` 已固定換行字元，複製到 Linux 也能跑。）

### 4.2 建立 Python 環境

**最簡單：** 什麼都不做，第一次執行 `start.bat` / `start.sh` 時會自動建立 `.venv` 並安裝套件。

**手動：**

```bash
# Windows（python 不在 PATH 時，用完整路徑，例如 C:\ProgramData\anaconda3\python.exe）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# Linux
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

若新版套件出問題，改用最後驗證過的版本：`pip install -r requirements.lock.txt`。

### 4.3 填設定（新機器才需要）

1. 開啟 `config.ini`，把每個 `model =`、`mmproj =`、`model-draft =`、`chat-template-file =`
   改成本機的實際路徑。
2. 開啟 `pipeline/settings.json`，改 `ROOT_PATH`（資料根目錄）、`IMAGE_TARGET_ROOT`
   （圖片資料夾）、`DB_*`（資料庫）。
3. 執行 `python env_from_settings.py`——把共用值同步到 `.env`。
4. 開啟 `start.bat`（或 `start.sh`），把最上面的 `LLAMA_SERVER` 改成 `llama-server` 的路徑。
5. 執行 `python setup_db.py`——建立資料庫、`vector` 擴充與 schema（已存在則跳過）。
6. 執行 `python doctor.py --all`——由上而下修正每一行 `[FAIL]`。

## 5. 每日操作：啟動、確認、停止

### 5.1 啟動（一鍵）

前提：PostgreSQL 服務已在執行（Windows 開機自動啟動；可在「服務」看 `postgresql-x64-18`）。

- **Windows：** 在程式資料夾雙擊 `start.bat`（或在命令列執行）。
- **Linux：** `./start.sh`

腳本會依序：建立／啟用 `.venv` → 安裝套件 → 啟動路由並載入四個模型（約 1 分鐘）→
執行 `doctor.py` 預檢 → 啟動後端。看到 `Uvicorn running on http://0.0.0.0:8079` 即完成。

路由已在執行、只要啟動後端時：`run.bat` / `./run.sh`。

### 5.2 確認服務正常

```bash
curl http://localhost:8079/health          # 應回 {"status":"ok"}
curl http://localhost:11400/v1/models      # 應列出模型名稱
python doctor.py --live                    # 全面檢查，含真實的模型呼叫
```

或直接用瀏覽器開 http://localhost:8079/ ，輸入「HGW20 load capacity」按 Send。

### 5.3 停止

- 後端：在執行 `start.bat` 的視窗按 **Ctrl+C**。
- 路由：關閉標題為 `llama-router` 的視窗（Windows），或在 Linux 的 `start.sh` 按 Ctrl+C 會一併停止。
- PostgreSQL 不需要停。

### 5.4 讓服務開機自動啟動（選用）

Windows：工作排程器 → 建立基本工作 → 觸發程序「當電腦啟動時」→ 動作「啟動程式」→
`C:\Users\User_11\Desktop\HIWIN\HIWIN_Dem\HIWIN_Support_Agent\start.bat`，「起始於」填程式資料夾。
Linux：以 systemd 服務執行 `start.sh`。

## 6. 使用系統

### 6.1 展示頁（最快的測試方式）

瀏覽器開 http://localhost:8079/ ：輸入問題、選語言（en / jp / tc / sc）、Send。
勾選 **Debug view** 可看到：搜尋了哪些資料表、每次搜尋的結果、完整性檢查的逐段結果、
耗時與 token。**答覆怪怪的時候先看這裡。**

### 6.2 API（給其他系統串接）

```bash
curl -X POST http://localhost:8079/chat -H "Content-Type: application/json" \
  -d "{\"prompt\": \"HGW20 的動態負荷是多少？\", \"language\": \"tc\"}"
```

回傳 JSON：`response`（Markdown 答覆）、`sources`（引用頁碼／檔名）、`trace`（工具呼叫）、
`metrics`（耗時）。語言代碼：`en` 英文、`jp` 日文、`tc` 繁中、`sc` 簡中。
從其他電腦呼叫時把 `localhost` 換成本機 IP（後端綁 `0.0.0.0`，注意防火牆）。

### 6.3 批次測試

```bash
python run_prompts.py                              # 送出 examples/ 內所有範例
python run_prompts.py my_questions.jsonl --timeout 900
```

結果存為 `results_<時間>.json`，並印出每種呼叫的耗時。調整設定前後各跑一次比較。

### 6.4 查詢對話記錄

所有對話都存在資料庫 `hiwin_cs_db.chat_logs`。用 pgAdmin 或 psql：

```sql
SELECT created_at, language, latency_ms, left(prompt, 60), left(response, 80)
FROM hiwin_cs_db.chat_logs ORDER BY created_at DESC LIMIT 50;
```

psql 位置（Windows）：`C:\Program Files\PostgreSQL\18\bin\psql.exe -U postgres -d hiwin_rag_db`

## 7. 新增或更新產品資料（跑管線）

> ⚠️ **重新匯入已存在的文件前，先讀 [INGESTION_DEFECTS.md](INGESTION_DEFECTS.md)。**
> 滾珠螺桿型錄有幾頁曾在資料庫中手工修正；重新匯入會把錯誤帶回來。

### 7.1 新增一份 PDF

1. 把 PDF 放到 `<ROOT_PATH>\PDFs\<產品名稱>\<檔名>.pdf`。
   `<產品名稱>` 會成為資料表名稱（例如 `Ballscrew` → `data_ballscrew`）；沿用既有資料夾名稱。
2. 開啟 `<ROOT_PATH>\PDF_Config.yaml`，加入一筆：
   ```yaml
   Ballscrew:
     新型錄-(C).pdf:
       language: tc            # en | jp | tc | sc
       pages_to_exclude: [0]   # 要略過的頁（從 0 起算，例如封面）
   ```
3. 確認路由在執行（`start.bat` 已啟動）。管線會自動載入它需要的模型，過程中會暫時
   擠掉服務用的模型；**請在沒人使用系統的時段進行**。
4. 執行管線（三選一，建議 GUI）：
   ```bash
   .venv\Scripts\activate
   cd pipeline
   python gui.py          # 圖形介面：設定畫面 → Save & Launch → Start Pipeline
   python tui.py          # 終端機介面
   python Pipeline.py     # 無介面
   ```
   已處理過的文件會自動略過，只處理新的。一份型錄依頁數可能需要數十分鐘到數小時。
5. 完成後確認：
   ```bash
   cd ..
   python inspect_metadata.py     # 新文件的列應出現在對應資料表
   ```
   然後到展示頁問一個只有新型錄才答得出的問題。
6. 做一份資料庫備份（§9）。

### 7.2 更新（換新版）一份 PDF

用**相同檔名**替換 PDF，從 `<ROOT_PATH>\checkpoint.json` 刪掉該文件的項目，再跑管線；
舊列會被刪除、新列以新版本號寫入。

### 7.3 移除一份文件

```sql
DELETE FROM hiwin_rag.data_ballscrew
WHERE metadata_->>'file_name' = 'Ballscrew_ballscrew-(c)_tc';
```

並刪掉 `checkpoint.json` 中的對應項目。

## 8. 搬到另一台機器

1. 在新機器完成 §3 準備、§4.1–4.2 安裝。
2. 複製模型檔與 `templates\qwen.jinja`；改 `config.ini` 的路徑。
3. 安裝 PostgreSQL + pgvector；填 `pipeline/settings.json` → `python env_from_settings.py`
   → `python setup_db.py`。
4. 舊機器匯出資料庫、新機器匯入（§9.1、§9.2）。
5. 還原圖片資料夾（§9.3）。
6. `python doctor.py --all` 全綠後，`start.bat` / `./start.sh`。

PDF、ONNX 模型與 `PDF_Config.yaml` 只有打算在新機器跑管線時才需要一起搬。

## 9. 備份與還原

### 9.1 備份資料庫（建議每週）

```bash
"C:\Program Files\PostgreSQL\18\bin\pg_dump.exe" -h localhost -p 5432 -U postgres -d hiwin_rag_db -Fc ^
  -n hiwin_rag -n hiwin_cs_db ^
  -T "hiwin_rag.bak_*" -T "hiwin_rag.repair_backup_*" -T "hiwin_rag.link_backup_*" ^
  -f hiwin_rag_db_%DATE:~0,4%%DATE:~5,2%%DATE:~8,2%.dump
```

（Linux 把 `^` 換成 `\`，日期用 `$(date +%Y%m%d)`。）備份檔與模型檔放在一起保存。

### 9.2 還原資料庫

先在目標機器執行 `python setup_db.py`，再：

```bash
pg_restore -h localhost -p 5432 -U postgres -d hiwin_rag_db --no-owner --no-privileges hiwin_rag_db_XXXX.dump
```

目標 PostgreSQL 比來源**舊**時，改用純 SQL 匯出（`-Fp`）並以 `psql -f` 載入；詳見
README §9「備份與搬移資料庫」。還原後 `python doctor.py` 應顯示 28 張 `data_*` 資料表。

### 9.3 還原圖片資料夾

目前機器的圖片資料夾尚未建立（答覆沒有圖示）。要建立：

1. 把 `C:\Users\User_11\Desktop\HIWIN\Final_Output.7z` 解壓到
   `C:\Users\User_11\Desktop\HIWIN\Final_Output`（4.5 GB）。
2. `cd pipeline` 後執行 `python -m ingestion.Ingest --assets-only`（只複製圖片，不動資料庫）。
3. 重啟後端；`python doctor.py` 應顯示 `[PASS] IMAGE_STATIC_ROOT`。

### 9.4 其他要備份的東西

- 程式與設定：儲存庫本身（`.env`、`settings.json`、`config.ini` 都已納入版控）。
- 輸入資料：`PDFs\`、`PDF_Config.yaml`、`PP-DocLayout-PlusL.onnx`（只有重建才需要）。

## 11. 調整回答的行為

| 想改什麼 | 改哪裡 | 之後 |
|---|---|---|
| 語氣、回答格式、什麼問題不回答 | `prompts\System_prompt.md`（整體規則）、`prompts\skills\<語言>.md`（各語言的分類與客服表單範本） | 直接生效 |
| 回答太簡略、漏列型號 | `.env`：確認 `COMPLETENESS_PASS_ENABLED=true`、`GRADING_ENABLED=false`；可調高 `RERANK_TOP_K` | 重啟後端 |
| 回答太慢 | `.env`：降低 `RERANK_TOP_K`；`config.ini` 的 aux 模型可調高 `parallel` | 重啟 |
| 模型參數（溫度、脈絡長度） | `config.ini` 各區段 | 重啟路由 |
| 客服表單網址 | `prompts\skills\*.md` 內的 URL | 直接生效 |

改動前後各跑一次 `python run_prompts.py` 比較。細節見 [MAINTENANCE.zh-Hant.md](MAINTENANCE.zh-Hant.md) §2。

## 12. 故障排除速查

先跑 `python doctor.py --all`，它會指出多數問題。常見狀況：

| 現象 | 處理 |
|---|---|
| `start.bat` 說找不到 Python | 安裝 Python 3.12 並勾選 Add to PATH，或執行前 `set PYTHON=C:\ProgramData\anaconda3\python.exe` |
| `router not reachable` / 展示頁一直「Thinking」 | 路由沒開：跑 `start.bat`；看 `llama-router` 視窗有無錯誤 |
| `llama-router` 視窗一閃就關 | `config.ini` 的模型路徑錯，或 VRAM 不足（GPU 0 被別人占用）；`nvidia-smi` 查看 |
| `password authentication failed` | `.env` 的 `DB_PASSWORD` 錯，或 `DB_PORT` 指到 5433（別人的 PostgreSQL） |
| `database "hiwin_rag_db" does not exist` | `python setup_db.py`，再還原備份 |
| `extension "vector" is not available` | 該 PostgreSQL 沒裝 pgvector；見 README §9 |
| 回答說「No results for language」 | 送的語言代碼與資料庫不符；`python inspect_metadata.py` 查看 |
| 回答有時漏型號、有時完整 | 確認路由用的是本專案的 `config.ini`（`parallel = 1` 才有穩定結果） |
| 第一題等很久（30 秒以上） | 剛跑完管線，模型被擠掉後正在重新載入；等第一題完成即恢復 |
| 圖片顯示不出來 | 圖片資料夾未建立（§9.3） |
| 管線最後出現 `UnicodeEncodeError cp950` | 舊版程式；資料其實已匯入。更新到最新版即可 |
| 延遲從 1 分鐘變成 30 分鐘以上 | 模型跑到別人正在用的 GPU；確認 `start.bat` 有 `CUDA_VISIBLE_DEVICES=0` |

更多見 README §14「疑難排解」。
